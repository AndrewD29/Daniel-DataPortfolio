1. Azure Data Factory Pipeline Optimisation & Power BI Refresh Automation

Azure Data Factory Power BI API Azure SQL Azure Key Vault Pipeline Design

Situation

An operational Power BI report used by Network Management teams refreshed every 30 minutes and relied upon data loaded through an Azure Data Factory pipeline from the Network Management System. As data volumes increased, warehouse loading activities occasionally overlapped with Power BI refreshes, This caused a few issues such as no data loading in to the report and we can not manually refresh as we were already at the max allowed daily and driving support requests to investigate discrepancies.

Task

Review and modify the existing Azure Data Factory design so Power BI datasets could only refresh after all ingestion and warehouse processing activities had completed successfully. The solution also needed to maintain secure authentication, operational logging and failure handling.

Action

I analysed the existing pipeline and identified that the Power BI refresh process could execute independently of the warehouse load sequence. To resolve this, I amended the design so source ingestion completed first, followed by the warehouse loading stored procedure responsible for populating reporting dimension tables.

Once the warehouse load completed successfully, a Web Activity was introduced to call the Power BI REST API and trigger a dataset refresh. Authentication was handled securely through a Service Principal with credentials stored within Azure Key Vault rather than embedded directly inside the pipeline.

Existing pipeline logging was retained and enhanced to capture start and finish events, creating a clear audit trail and improving troubleshooting capabilities. Failure handling was also configured to prevent downstream activities executing whenever an upstream process failed. 

{
    "name": "Refresh_Power BI Report",
    "type": "WebActivity",
    "dependsOn": [
        {
            "activity": "calling usp_load_dim_nms_incident",
            "dependencyConditions": [
                "Succeeded"
            ]
        }
    ]
}

This ensured Power BI refreshes could only execute after warehouse processing had completed, eliminating timing conflicts between ingestion and reporting layers.

Result

100% Warehouse-first refresh sequencing
Reduced Refresh failures and timing clashes
Improved Operational reporting reliability

The revised design ensured Power BI reports could only refresh against completed and validated warehouse data. This improved confidence in reporting outputs, reduced support effort associated with refresh investigations and demonstrated secure integration across Azure Data Factory, Azure SQL, Azure Key Vault and the Power BI REST API.
